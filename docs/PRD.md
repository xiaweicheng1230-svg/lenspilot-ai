# LensPilot AI 产品需求文档

## 1. 产品背景

摄影新手往往知道照片“有问题”，却无法定位问题来自曝光、快门、对焦、构图还是现场光线。通用教程解释概念，普通 AI 点评描述观感，但两者都很难把用户当前照片、真实拍摄参数和下一次操作连接起来。

## 2. 产品定位

LensPilot AI 是一个结合照片内容、EXIF 参数、拍摄目标和历史表现的多模态摄影教练。核心任务不是判断照片是否好看，而是帮助用户理解原因并完成下一次拍摄。

## 3. 目标用户

- 刚购买相机、仍依赖自动模式的摄影新手
- 希望理解参数的手机摄影用户
- 需要复盘照片的年轻内容创作者

## 4. 核心痛点

1. 拍糊、过曝、欠曝或噪点严重时不知道原因。
2. 学过 ISO、光圈和快门，但不会在真实场景组合使用。
3. 通用 AI 建议笼统，缺少可执行设置。
4. 多次拍摄后仍不知道自己的长期优势与弱点。

## 5. 核心价值

形成“诊断问题—解释原理—建议下一张—历史复盘—针对性练习”的学习闭环。

## 6. 用户故事

- 作为夜景摄影新手，我希望系统结合快门和 ISO 解释模糊与噪点，让我知道下一张先改什么。
- 作为人像用户，我希望系统解释背景不够虚的可能原因，而不是只说主体不突出。
- 作为持续练习的用户，我希望看到由历史评分计算出的能力画像，而不是随机生成的标签。
- 作为谨慎的用户，我希望知道哪些内容来自 EXIF、哪些是 AI 判断、哪些存在不确定性。

## 7. MVP 功能需求

### P0

- JPEG、PNG、WebP 上传、预览和验证
- EXIF 提取、标准化和缺失降级
- 拍摄类型、目标和备注输入
- 图片与上下文共同参与的结构化 AI 分析
- 综合评价和六项摄影维度诊断
- “下一张怎么拍”参数范围、原因和限制说明
- 历史记录、报告回看、反馈与纠错
- 五张有效报告后生成确定性摄影画像
- 基于历史问题生成七天学习计划
- 真实 AI Provider 与明确标识的 Mock Provider
- Prompt 版本、响应延迟、错误状态和重试

### P1

- 报告分享与导出
- 登录和多用户隔离
- RAW 文件基础支持
- Prompt A/B 测试

## 8. 非功能需求

- 主要流程适配 375px 及以上移动端。
- API 不在日志或响应中泄露密钥。
- 上传内容通过格式、体积和像素限制校验。
- AI 输出必须经过后端 Schema 验证。
- 数据库支持从 SQLite 迁移到 PostgreSQL。
- 无 AI Key 时仍能通过 Mock Mode 体验完整流程。

## 9. 验收标准

1. 新环境可根据 README 启动前后端。
2. 有无 EXIF 的合法图片都能完成上传。
3. 非图片、超限和损坏文件返回可理解错误。
4. AI 返回字段缺失或格式错误时不会导致白屏。
5. 报告明确标记真实 AI 或 Mock / Demo。
6. 雷达图只使用数据库中的历史评分计算。
7. 评测文档不包含未经实际运行的数据。

## 10. 产品风险

- 模型可能把主观审美包装成事实。
- EXIF 可能被平台移除或由编辑软件改写。
- 不同相机与镜头的字段命名并不一致。
- 建议参数受现场光线、防抖、主体速度和设备能力影响。
- 上传照片可能包含人物与位置隐私。

缓解方式包括：证据来源标记、不确定性说明、GPS 默认剔除、结构化校验、反馈纠错和真实案例评测。
